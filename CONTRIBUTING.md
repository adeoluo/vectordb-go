# Contributing

## Development setup

```bash
make all
```

## Workflow

1. Branch from `main` (`feat/...`, `fix/...`, `docs/...`).
2. Use Conventional Commits (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`).
3. Keep changes focused. Continuous integration must be green before merge.

## Standards

- Behavior changes come with tests; bug fixes come with a test that fails without the fix.
- Numbers quoted in the README are regenerated by the command that produced them.
- See [AGENTS.md](AGENTS.md) for the layout, commands and conventions.

## Releases

Releases are cut locally by the maintainer, so tags and release notes are authored by a person:

```bash
scripts/release.sh --dry-run   # show the inferred version and notes
make cut-release               # bump, regenerate CHANGELOG.md, tag, push, publish
```

The version comes from the commits since the last tag: `feat` bumps the minor version,
`fix` and the rest bump the patch version. [CHANGELOG.md](CHANGELOG.md) is generated by
[git-cliff](https://git-cliff.org) from the same commits.
